# Evaluation and verification

## Software checks

Use Python 3.12. Install `sprint2_demo/requirements.txt` for Streamlit tests. The root writing tests and scripted backend tests use fixtures or mocked providers; no API calls are required.

| Working directory | Command | Coverage |
|---|---|---|
| Repository root | `python -m unittest discover -s tests -v` | Root writing contracts, rollback, budgets, review logic and repository layout |
| Repository root | `python -m src.writing validate --package examples/research_package.json --v0 examples/v0.json` | Synthetic six-section fixture |
| `sprint2_demo/backend/` | `python -m unittest discover -s tests -v` | Pinned writing backend and feedback-stability regression tests |
| `sprint2_demo/` | `python -m unittest discover -s . -p 'test_*.py' -v` | Upload validation, handover integration, citation policy, launch guards and budgets |
| `sprint2_demo/ui/` | `python -m unittest test_app test_research test_detection -v` | Navigation, real saved evidence, upload isolation, offline detector and live-launch guards |

Do not run the collection, generation, detector-training or live-run scripts as test-discovery substitutes. They may download data, replace existing results or incur model charges. See [the detector guide](../src/detection/README.md) for experiment commands; preserve recorded outputs when rerunning them.

## Different kinds of evidence

| Evidence | Interpretation |
|---|---|
| Offline scripted tests | Software behaviour under controlled fixtures, not model quality |
| Recorded live writing runs | Development observations for the supplied package and configuration |
| Deliberate 20 → 21 safety edit | A controlled preservation test, not an error spontaneously generated by the writer |
| Detector validation and held-out files | Recorded detector experiments; inspect partitioning, baselines and limitations before drawing broader conclusions |
| Dry-run outputs | Software exercises; not real model performance |
| Human response template or form | Evaluation preparation, not completed ratings |

## Measures and remaining work

Report writing-review counts separately from detector scores. Neither establishes factual accuracy or authorship. Assess writing quality and preservation independently; a lower optimised score alone does not establish better writing.

The existing detector reference corpus may differ in genre and generator from test text. Its documentation records those limitations. Independent human evaluation and systematic failure analysis remain necessary. The current research proposal does not contain completed bilingual QA experiment results.

## Human-review materials

Root writing `export-human` creates separated rater and private condition-key materials in a fresh output directory. The detector's historical `results/detection/human_eval/PRIVATE_answer_key.csv` is already tracked and therefore not private; naming a file `PRIVATE` does not restrict access.

Do not distribute keys or identifiable responses to raters or commit new ones. Use an ignored local `.private/` location or approved restricted storage for new private evaluation materials. The existing detector builder writes its key next to public materials, so review its output before committing or distributing it. Ignoring a folder does not remove earlier commits. If raters have seen published keys, use fresh blinded items.

The original recorded outputs are retained for provenance, not silently rewritten to claim stronger verification or evaluation results.
